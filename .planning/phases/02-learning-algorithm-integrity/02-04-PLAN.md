<objective>
Complete BUGFIX-06 transaction consolidation:

1. D-12: Remove the trailing `conn.commit()` from `update_device_bucket()` (learning.py:199) and `log_rejection()` (learning.py:238). (The third inner commit, in update_segment_stats, was already removed in Plan 02.) The single `conn.commit()` at routes.py:210 — already outside the per-segment loop — becomes the only commit for the entire ride.
2. D-13: Hoist the `if device_bucket: update_device_bucket(conn, device_bucket)` call out of the per-segment loop (currently routes.py:132-135, redundantly called once per segment) so it runs exactly once per ride, immediately after `device_bucket = ride.device_bucket` and before the loop.

Purpose: Today a 50-segment ride issues ~100 commits (per-segment device-bucket + stats commits), defeating SQLite WAL's single-writer/one-transaction-per-POST design and creating a partial-write repudiation risk on mid-ride failure. Consolidating to one commit is both a performance fix and strictly safer (full rollback on error).

Output: two commit removals in learning.py, one hoist in routes.py, two new integration tests.

This is Wave 4 (after Plan 02 removed the update_segment_stats commit and Plan 03 touched routes.py::get_config) to avoid concurrent edits to the same files.
</objective>
