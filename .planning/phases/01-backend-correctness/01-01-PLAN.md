<objective>
Convert `backend/app/db.py`'s `get_connection()` from a plain function returning a `sqlite3.Connection` into an `@contextlib.contextmanager` generator (D-13) that guarantees `conn.close()` on every exit path (return, `raise HTTPException`, or unhandled exception). This closes the P0 SQLite file-descriptor leak (BUGFIX-01) where any exception between `get_connection()` and the manual `conn.close()` in a route handler leaks the connection. The `get_eta` handler builds its response inside the `with` block regardless of the later JSONResponse deprecation change (D-14).

Scope note (D-15 reconciled): D-15 scopes the leak FIX to routes.py handlers, but `@contextmanager` changes the call CONTRACT globally — so idempotency.py, rate_limit.py, bootstrap.py, and all test call sites also require the mechanical `with` syntax update (behavior-preserving, not a leak fix). This is unavoidable and covered in Task 3.

Because `@contextmanager` changes the global call contract of `get_connection()`, EVERY call site in the codebase (application code AND tests) must simultaneously switch to `with get_connection(...) as conn:` syntax. This is an atomic, all-or-nothing conversion — a single missed call site receives a `_GeneratorContextManager` object instead of a `sqlite3.Connection` and raises `AttributeError` on the first `.cursor()` call.

Purpose: Eliminate the highest-severity reliability defect in the phase (DoS via FD exhaustion under exception-triggering traffic) and establish the connection-management substrate that Plans 02 and 03 build on.
Output: `db.py` context-manager conversion, all 15 application call sites updated, all 24 test call sites updated, and a new forced-exception connection-leak test.
</objective>
