<objective>
Add `scripts/update_gtfs.sh <path-to-new-gtfs.zip>` (DATA-04): a bash orchestrator that safely refreshes GTFS data without losing learning history. It takes a local zip path (D-10 — no network fetch), takes a pre-refresh backup (D-14), stops `bmtc-api` (D-15), clears only the 7 GTFS-source tables (D-11), re-bootstraps via the existing `app.bootstrap` (which refreshes `schedule_mean` only, preserving Welford history — RESEARCH finding #2), validates post-refresh row counts against a >50% delta threshold on the 7 GTFS tables (D-13), and on any failure auto-restores the backup via `restore.sh` and exits non-zero (D-14), otherwise restarts the service. Backup/restore/parse logic is reused verbatim from existing scripts — no reimplementation.

Purpose: turn a risky manual re-bootstrap into a scripted, auditable, self-healing-on-failure operation that cannot delete `segment_stats`/`rides`/`ride_segments`.
Output: `update_gtfs.sh`, a tiny synthetic GTFS fixture + its generator, and an integration test covering both the passing and the failing-rollback paths.
