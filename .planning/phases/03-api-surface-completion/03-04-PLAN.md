<objective>
Enrich `GET /v1/eta` (API-04): add `from_stop_name`, `to_stop_name`, and `route_short_name` to the nested `SegmentInfo` object, populated from GTFS via a JOIN, so mobile clients render human-readable ETA results without a follow-up `/v1/stops` or `/v1/routes` lookup.

Locked decisions: D-18 (fields added ONLY to nested SegmentInfo, not the flat deprecated fields), D-19 (`route_long_name` explicitly NOT added — stick to the 3 locked names), D-20 (orphaned reference → null that field, still 200, never 500 — via `LEFT JOIN`), D-21 (docs drive-by: replace the misleading `"route_id": "335E"` example with a realistic compound `route_id` + separate `route_short_name`, since `335E`-style codes are actually route_short_names), D-22 (no mobile changes — fields are additive/optional so no client breaks).

CRITICAL (RESEARCH.md, single highest-risk detail): the enrichment query MUST use `LEFT JOIN`, never `INNER JOIN`. An INNER JOIN drops the whole row when any one of from_stop_id/to_stop_id/route_id is orphaned, which would make the ETA lookup appear to fail rather than partially enrich. The 3 new SegmentInfo fields MUST be `Optional[str] = None` to accept the resulting NULLs.

Purpose: one-call human-readable ETAs.
Output: extended SegmentInfo, extended get_eta, 2 new tests, extended conftest fixture, docs/api.md update.

CLAUDE.md order: Task 1 spec, Task 2 RED tests + fixture extension, Task 3 GREEN implementation.
</objective>
