<objective>
Add `GET /v1/stops/{stop_id}` (API-01): returns single-stop detail (`stop_id`, `stop_name`, `stop_lat`, `stop_lon`, `zone_id`) plus a `routes` array of full `RouteResponse` objects for every route serving that stop.

Locked decisions implemented: D-07 (full stop fields + full RouteResponse entries), D-08 (no dedup by short_name — route_short_name is confirmed NOT 1:1 with route_id), D-09 (`ORDER BY route_short_name`), D-10 (orphaned stop → 200 + `routes: []`, never 404), D-11 (`HTTPException(404, detail={...})` matching `get_eta`'s style, not the `JSONResponse` style of sibling GTFS endpoints).

Purpose: Mobile clients can render a stop screen (name, position, serving routes) in one call instead of cross-referencing `/v1/routes`.
Output: 1 new route handler, 1 new Pydantic model, 3 new integration tests, 1 new/extended conftest fixture, 1 new docs/api.md section.

Follows CLAUDE.md's mandatory Spec-First → Tests → Code order: Task 1 updates `docs/api.md`, Task 2 writes failing tests + fixture (RED), Task 3 implements (GREEN).
</objective>
