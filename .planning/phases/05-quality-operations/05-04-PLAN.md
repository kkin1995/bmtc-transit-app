<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted fork PR → CI runner | A malicious PR could modify test code to exfiltrate secrets or abuse write permissions |
| CI job → repository | The workflow's granted permissions define its blast radius |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-08 | Information Disclosure | CI secret exfiltration via a malicious fork PR | high | mitigate | Trigger on `pull_request` (not `pull_request_target`, which would run untrusted head code with base secrets); use no real secrets — tests inject a dummy `BMTC_API_KEY` via `conftest.py`, so there is nothing to exfiltrate |
| T-05-09 | Elevation of Privilege | over-privileged workflow token | high | mitigate | Declare `permissions: contents: read` at the top level — the test job needs no write access (ASVS V14) |
| T-05-10 | Tampering | subprocess-based tests fail on the runner due to hardcoded PATH | low | accept | `ubuntu-latest` ships sqlite3/gzip under `/usr/bin` matching the tests' hardcoded PATH (Pitfall 8); pinning to a single ubuntu runner (no matrix, D-13) keeps this a non-issue unless a macOS/Windows runner is later added |

*No new Python/npm packages introduced (RESEARCH Package Legitimacy Audit: zero new dependencies). `astral-sh/setup-uv` and `actions/checkout` are GitHub Actions from reputable orgs, pinned by major tag — not entries in this project's dependency tree, so the pip/npm supply-chain (T-*-SC) checkpoint does not apply.*
</threat_model>
